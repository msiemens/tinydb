# ADR-021: Edit existing files by exact replacement, and keep the Groq key from model-written code

- **Status:** Accepted. Changes the implementer's tools from ADR-005 and the secret list from ADR-012.
- **Date:** 2026-11-21

## Context

On [run 44889133139](https://github.com/Anilkumark17/tinydb/actions/runs/44889133139) (issue #3), the stage 3 build check failed:

```
File "tinydb/table.py", line 820
SyntaxError: unterminated triple-quoted string literal (detected at line 829)
```

The implementer's only edit tool was `write_file`, which replaces a whole file. `tinydb/table.py` has 854 lines, about as many tokens as the 8192-token output cap, so the rewrite was cut off near the end. Issue #1's rewrite of the same file happened to fit.

While fixing this, `tools.clean_env()` was found to remove `GEMINI_API_KEY`, `GH_TOKEN`, `GITHUB_TOKEN` and `AUTOSE_PAT`, but not `GROQ_API_KEY`, added in ADR-017. Tests that run model-written code could read it.

## Decision

The implementer gets `replace_in_file(path, old, new)`. It changes `old` only if it occurs exactly once, and otherwise returns how many matches it found without writing. The same deny list as `write_file` applies. The implementer prompt says to use it for every change to an existing file and to keep `write_file` for new files.

`GROQ_API_KEY` is added to `SECRET_ENV`.

## Alternatives considered

Raise the output cap. The file could still outgrow it, and every call would cost more.

A unified-diff tool. Models often produce diffs that do not apply, and the error is harder to act on.

## Consequences

Edits cost far fewer output tokens and cannot cut a file short.

An edit fails if `old` is not copied exactly; the tool says so, and the implementer can read the file again.

Run 44889133139 stays in `results/` as a build failure under the old tool.
