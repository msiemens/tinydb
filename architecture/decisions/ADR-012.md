# ADR-012: Model-written code runs without secrets, and the test command is `uv run pytest tests`

- **Status:** Accepted. Supersedes the test command and the secret handling in ADR-005. Stage 4 ran `uv run pytest tests`. The pytest process did not receive the API keys.
- **Date:** 2026-11-20

## Context

ADR-005 keeps the Gemini key out of prompts, artifacts and tool arguments. It does not say what happens when pytest runs. Stage 4 runs the tests the tester model just wrote, and the reviewer's `run_tests` runs the pull request's code. A child process inherits the environment of the runner process, which holds `GEMINI_API_KEY`. A test that reads `os.environ` could print or send the key. The issue text is untrusted and can steer a model into writing such a test.

ADR-005 and ADR-007 also give the command `uv run pytest`. `pytest.ini` has no `testpaths`, so that command collects every `test_*.py` file in the repository, including the agent's own offline tests under `autose/tests/`. A failure there would be reported as a TinyDB test failure.

`uv run` re-syncs the environment and can rewrite `uv.lock`, which would then appear in `diff.patch`.

## Decision

All subprocesses that run repository or model-written code (`uv sync`, the import check, pytest, the reviewer's `run_tests`) get a cleaned environment: `GEMINI_API_KEY`, `GH_TOKEN`, `GITHUB_TOKEN` and `AUTOSE_PAT` removed, and `UV_FROZEN=1` set.

The one test command is `uv run pytest tests -q`. It covers the project's own suite and the tester's new file in `tests/`.

## Alternatives considered

Rely on the prompt to tell the model not to write tests that read the environment. A prompt is the weakest fence, as ADR-008 already argues.

Run pytest in a separate job with no secrets. It is cleaner, but the builder needs the result in the same loop, and a job per attempt multiplies the Actions minutes and the artifact hand-offs ADR-002 wanted to avoid.

Add `testpaths = tests` to `pytest.ini`. It changes a project file for a workflow concern.

## Consequences

The model API call happens in the runner process, not in a child process, so removing the key from child processes costs nothing. A test that legitimately needs an environment variable that was removed would fail. TinyDB's tests do not.

A pull request that breaks only `autose/tests/` will not be caught by stage 4. Those tests run when someone runs them by hand.
