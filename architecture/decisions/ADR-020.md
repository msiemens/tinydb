# ADR-020: Raise the tool-round limit from 8 to 16

- **Status:** Accepted. Changes one number in ADR-009.
- **Date:** 2026-11-21

## Context

ADR-009 allowed each model call at most 8 tool rounds. Issue #1 finished inside that limit.

On [run 44887740431](https://github.com/Anilkumark17/tinydb/actions/runs/44887740431) (issue #2, copying documents between databases), `gemini-3.5-flash-lite` returned HTTP 503, the ADR-018 fallback `gemini-3.1-flash-lite` took over, and the implementer stopped with `BudgetExceeded: implementer: more than 8 tool rounds`. The job had used 1m43s of its 20-minute limit.

Issue #2 touches more of the code than issue #1, and the fallback model may need more rounds than the primary.

## Decision

`MAX_TOOL_ROUNDS` is 16. The 20-minute job limit and the 8192-token output cap stay as ADR-009 sets them.

## Alternatives considered

Keep 8 and record issue #2 as a failure. That measures the limit more than the workflow.

Re-run unchanged. That depends on the primary model being available, which it often was not.

## Consequences

Run 44887740431 stays in `results/` as a budget failure under the old limit. Issue #1 ran under 8 rounds and later issues under 16, and the report states this.

A stuck agent now costs up to twice as many model calls before it stops. The job time limit still bounds it.
