# ADR-018: Try `gemini-3.1-flash-lite` before Groq, and cap Groq output

- **Status:** Accepted. Extends ADR-015 and ADR-017.
- **Date:** 2026-11-20

## Context

`gemini-3.5-flash-lite` returned HTTP 503 in the builder on runs 44784749664, 44786814645 and 44787871458. On the last run the ADR-017 fallback reached Groq, which returned HTTP 413: the free tier allows 8000 tokens per minute and counts the requested `max_tokens` (8192) on top of the prompt.

ADR-015 recorded that `gemini-3.1-flash-lite` also answered on this key. It has its own quota and is not affected by load on the 3.5 model.

## Decision

After the requested model fails with 429 or 5xx, `autose/llm.py` tries `gemini-3.1-flash-lite`, then Groq. Calls to Groq ask for at most 2048 output tokens. The usage log records the model that answered.

## Alternatives considered

Groq only, with a smaller output cap. The builder's later tool rounds carry whole source files, which pass 8000 tokens on their own, so Groq's free tier cannot carry the builder.

Change the primary model to `gemini-3.1-flash-lite`. That would also change the model for runs that work today on 3.5 lite.

## Consequences

A run can mix up to three models. The report must name the models that answered each run, taken from the usage log.

Groq remains useful only for short calls such as the reviewer's verdict.
