# ADR-014: Call `gemini-3.8-flash` for every role

- **Status:** Superseded by ADR-015. `gemini-3.8-flash` did not finish a free-tier run.
- **Date:** 2026-11-20

## Context

ADR-006 chose `gemini-2.5-flash` for the analyst, implementer and tester, and `gemini-2.5-pro` for the reviewer. A model-list call on 20 November still listed both ids. The first real run, [Actions run 44694126303](https://github.com/Anilkumark17/tinydb/actions/runs/44694126303), reached the analyst and Gemini returned HTTP 404: `models/gemini-2.5-flash` is no longer available to new users, and the replacement it named was `models/gemini-3.8-flash`.

A direct `generateContent` call then showed:

- `gemini-2.5-pro` returns the same 404, and names `gemini-3.1-pro-preview` as its replacement.
- `gemini-3.1-pro-preview` returns HTTP 429, quota exceeded, on this key.
- `gemini-3.8-flash` is the id the 404 tells new users to call.

The split between roles in ADR-006 was about independence and cost. The ids themselves are what the run falsified.

## Decision

`autose/__init__.py` sets both `FLASH` and `PRO` to `gemini-3.8-flash`. Every role uses that id until this key can call a Pro model.

The reviewer stays a separate job, prompt, and token, as in ADR-008. The model id is no longer part of that separation.

## Alternatives considered

Keep calling `gemini-2.5-flash`. The run already showed that the API rejects it.

Use `gemini-3.1-pro-preview` for the reviewer only. That is the replacement the API named for Pro, and it would restore a different model id. This key has no quota for it, so the review job would fail after a successful build. A finished run matters more than the model split until the quota exists. When a Pro call succeeds, supersede this ADR and point `PRO` at that id.

## Consequences

The reviewer can share Flash's blind spots. ADR-008 still keeps the builder's transcript out of the review job. A rubber-stamp check in the verdict script is unchanged.

A later run that 404s on `gemini-3.8-flash` should supersede this ADR with the id the error names, rather than editing this file in place.
