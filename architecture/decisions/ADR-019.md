# ADR-019: Collect only `tests/` in CI, and wait only on pull-request checks

- **Status:** Accepted. Corrects the cause assumed in ADR-016.
- **Date:** 2026-11-21

## Context

ADR-016 assumed `Python CI` was red on `master` for a reason outside the project. The CI log of PR #17 shows the real cause. The test step runs `py.test` with no path, so pytest collects every test folder in the repository:

- `workflow/autose/tests/test_autose.py` has the same module name as `autose/tests/test_autose.py`, and collection stops with `import file mismatch`.
- `experiment/hidden_tests/` would also be collected, and 17 of its 20 tests fail by design.

Both folders were added for A3. TinyDB's own 228 tests pass.

Run 44790059127 then lost the release stage to a 25-minute CI timeout. `Python CI` runs on `push` and on `pull_request`, so every PR starts two copies of the matrix, and the ten macOS jobs queued for about 20 minutes.

## Decision

`pytest.ini` sets `testpaths = tests`, so CI runs TinyDB's suite only. The agent tests and the hidden tests are run on purpose, not by CI's default collection.

Stage 5 waits only on checks from the `pull_request` event and allows 30 minutes, inside the release job's 35-minute limit.

The ADR-016 rule stays: a check red on `master` does not block the PR.

## Alternatives considered

Remove macOS from the CI matrix. That changes upstream TinyDB's CI, which the workflow should not touch.

Rename one of the duplicate test modules. That fixes the import error but still collects the hidden tests.

## Consequences

`master` CI should turn green, so stage 5 judges the PR against a clean baseline.

A PR that breaks only a push-event check is not caught by stage 5. Both events run the same matrix, so this case should not occur.
