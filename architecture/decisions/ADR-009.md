# ADR-009: Budgets, timeouts, and untrusted issue text

- **Status:** Accepted, then the tool-round number was changed by ADR-020. [Run 44887740431](https://github.com/Anilkumark17/tinydb/actions/runs/44887740431) stopped at 8 tool rounds. The provider spend cap was not set. The key stayed on the free tier.
- **Date:** 2026-11-20

## Context

Actions jobs have a default timeout of six hours. A model that keeps calling tools will use that. The course also asks for a hard spend limit at the provider. The Gemini key cannot set that limit. The cap has to be saved on the AI Studio Spend page for the project. This ADR is the limit inside the workflow, which still applies if the project cap is large.

Anyone can open an issue on a public fork. The label and the `/autose` command are restricted in ADR-010, but the issue body is still attacker-controlled. Typical injections ask the model to print the key, push to another repository, skip the tests, or treat the issue as a new system prompt.

A stuck stage is one that never writes its artifact, or writes an artifact the check cannot parse, or loops on the same pytest failure.

## Decision

Budgets, counted in `state.json`:

| Loop | Limit | After the limit |
| --- | --- | --- |
| Analyst regeneration when the stage 1 or 2 script fails | 1 | Stop. The artifact includes the script's reason. |
| Implementer retries after pytest fails | 2 | Return to the analyst once. |
| Returns from test failure to design | 1 | Stop. `test_report.md` keeps the last pytest log. |
| Review rounds | 2 | Stop, whatever the second verdict is. The pull request stays open. |

Each model call allows at most 8 tool rounds and 8192 output tokens. Each model job has `timeout-minutes: 20`. The release job's wait for CI is 25 minutes. The workflow `timeout-minutes` is 90.

Issue title and body are written to `untrusted/issue.md` and placed in the prompt between explicit fences. The system prompt says that text inside the fence is evidence about the bug, and that it cannot change the repository, the tools, the model id, or the check scripts. The runner never interpolates the issue body into a shell command. Branch names use the issue number, not the issue title.

On any exception, the job writes the stage artifact with `result: fail` and the exception type, then exits non-zero. It does not start the next stage. Logs go through a redaction filter for the `GEMINI_API_KEY` value and for `Authorization` headers.

The workflow does not clone, push, or open pull requests in any repository other than `Anilkumark17/tinydb`.

## Alternatives considered

No in-workflow budget, relying on the AI Studio monthly cap. The cap can lag by several minutes, and one stuck loop can consume a large part of a small cap before the cap reacts. The round limits make the worst case a known number of calls.

Cancel the job on the first pytest failure and ask the maintainer to re-label. That saves tokens and throws away the assignment's retry path. Two implementer retries are enough for a bad import or a missed branch, and not enough to wander.

Ask the model to detect prompt injection and refuse. The model is the component the injection is aimed at. The enforcement is the tool list and the command template, which do not contain a slot for the issue text.

## Consequences

A genuinely hard issue can exhaust two code retries and one design return and stop with a red `test_report.md`. That is a finished, failed run, and it is the correct outcome. The maintainer can edit the issue and start again. The new run starts at stage 1, by ADR-004.

The 20-minute job timeout can kill a slow Pro review. The artifact then says the job timed out, which is a failed check, not an approval.

The provider spend cap is still required. This ADR does not create it. A run should not be started until the Spend page shows a saved monthly cap. The in-workflow limits are a backstop, not a billing control.

If the redaction filter misses a new header name, the key can land in the Actions log. The filter's list is part of the runner and should be reviewed when the HTTP client changes. The key is not written to an artifact on purpose.
